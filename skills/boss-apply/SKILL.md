# BOSS 自动投递

目标是完成用户授权数量的、符合其当次画像的 BOSS 沟通。把“发起沟通”和“附件简历发送”分开统计。普通沟通由网页“立即沟通”触发，不直接调用 BOSS 私有接口。

## 一句话启动与首次环境准备

用户说“用 $boss-apply 帮我投递 BOSS 岗位”即进入本流程，不要求用户懂脚本、终端、Python 或篡改猴。先读 [首次启动](references/startup.md)，由助手检测环境、选择可用执行路径并完成配置。收集画像可与只读环境检测并行；不要把安装命令作为给用户的作业。

有 Computer Use 时，即便没有 Python 或 Tampermonkey，也可用纯 Computer Use 路径完成相同筛选、去重和单次沟通流程，无须为了投递强制安装扩展。没有可用浏览器控制工具时先完成画像，准确说明需要启用的能力；不要声称已经启动或后台运行。

## 先补齐信息

读取本次对话和用户明确提供的材料；只询问缺失项，不要求重复填写已有信息。首次可合并询问：

> 为了按你的条件筛选，请补充：①学历/专业、毕业时间或工作经验；②目标岗位及优先级、相关技能和经历、明确不投的方向；③优先城市及是否接受其他城市/远程；④求职类型、到岗时间，实习则补充每周天数与时长；⑤本轮投多少个，还是今天累计达到多少个；⑥是否授权对筛选通过的岗位自动点击“立即沟通”，以及使用当前 BOSS 招呼还是你指定的内容。

薪资、融资阶段、规模、英语、院校/学历要求等仅在用户有要求或实质影响匹配时补问。将“真实背景”“硬约束”“偏好”“允许尝试的不满足项”分别保存；放宽筛选不能改写真实背景。没有语言或学历证明，不得在招呼里宣称有。不要默认任何岗位方向、城市、毕业年份、融资阶段、每日额度或豁免条件。

最低可启动条件：真实背景足以判断目标岗位；目标/排除方向与地域明确；数量口径明确；有可用且不失真的招呼；已获本轮自动沟通授权。简历仅在需要补充画像或发送附件时必需。若用户只要筛选，保持只筛选模式。

当前用户已经明确授权筛选通过即投递时，复述范围后直接执行，不重复索要授权。缺失授权只完成筛选。安装第三方扩展、首次安装脚本、验证码等按当前工具的确认规则处理；本技能不授予额外权限。

## 建立独立状态

读取 [执行与恢复](references/execution.md)。每个 BOSS 账号使用独立、固定的运行目录；画像、简历、台账都保存在那里，不写进技能目录。不同日期/批次沿用同账号台账、新建 run ID。技能包不内置或学习某个用户的私人画像。

读取已有 BOSS 台账和页面“继续沟通”状态去重；官网和其他平台记录不是 BOSS 已投证明。不要启动多个发送控制器，也不要重启已完成的批次。开始前核对 Chrome 登录账号、招呼内容、今日已用次数（若页面可见），并检查是否有未核验点击。

## 筛选并投递

1. 在用户指定浏览器用 Computer Use 读取实际页面。按用户方向与地域优先级搜索，从界面取得并核实搜索 URL，再加入队列。不能猜测城市编码、批量试探 URL、抓私有接口或规避平台限制。
2. 启动本地 runner 和浏览器脚本，默认只筛选。脚本读取完整岗位描述，每积累最多 5 个待评估岗位自动暂停。
3. 使用 `review` 读取候选，以当次画像逐个判断。先判断用户硬约束和求职类型，再判断实际职责、技能匹配和偏好权重；关键词命中不等于匹配。区分标题中的 AI/技术宣传与实际销售、运营、培训等职责。记录具体理由、分数和证据；未知关键条件记为待核实，不编造通过理由。
4. 用 `decide` 保存审核结果。先核验小批量分类、公司身份和去重是否正确。已有本轮投递授权且验证通过时，执行 `enable-send` 并从页面恢复，无需再确认每个岗位。没有授权则交付筛选清单。
5. 发送过程中持续审核下一批候选并恢复运行，直到达到授权目标、候选耗尽或实际阻塞。只处理本轮通过的岗位。偏好调整时先暂停、核验在途发送，建立新的画像版本和批次，保留原台账；重审尚未发送的候选。

投递原子顺序：本轮审核通过 → 核对岗位 ID 与“立即沟通” → SQLite 点击前占位 → 点击一次 → 同岗位按钮变为“继续沟通”或明确新发送回执 → 记成功。平台会自动发送预设招呼，绝不再追加同义自我介绍。未确认结果不得清除占位、重复点击或计为成功。

## 监督和结束

运行期间用 `status` 及必要页面核验监督，向用户报告已确认/目标和有意义的异常。页面在正常加载时不反复刷新。浏览器布局变化必须暂停、观察后修复，不能盲猜选择器继续发送。

额度提醒若只是剩余次数通知，可在授权范围内确认并核验后续状态；真正额度耗尽、账号退出、验证码、操作限制、发送含糊时停止相关动作。遵循工具的验证码确认/交接规则，不绕过验证，不切账号规避额度。

达到目标自动停止；导出本轮结果并关闭服务。说明新增已确认数、累计数（有证据才说）、未确认数和附件是否发送。耗时取事件时间，并说明是否含筛选/修复。不得将后台进程仍存活当成持续托管承诺，也不要自行创建每日定时投递。

附件发送是额外范围：仅在明确授权后按用户指定文件/已确认唯一现有附件操作；必要时核对文件名、内容及哈希。发送后核验新附件气泡和送达状态；本附带 runner 只自动发起沟通，不负责附件发送。
