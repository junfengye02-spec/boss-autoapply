# IAB / Playwright 与桌面控制

## 先查能力，再判断不可用

不根据“自定义 API 登录”“未启用桌面 Computer Use”推断浏览器不可用。检查当前实际工具与文档：IAB 内置浏览器、已连接 Chrome、浏览器 Playwright 接口、桌面操作分别检测。只有网页搜索/抓取或地址栏上下文，不代表具备页面点击能力。

尊重用户指定浏览器。未指定时，复用已连接且登录的 Chrome；否则可试 IAB，再考虑桌面操作。IAB 通常独立于 Chrome 登录会话，不能假定共享 Cookie。不要从另一浏览器偷偷导出 Cookie 或凭据。

## 无发送探测

1. 通过当前工具文档规定的入口创建或选择 BOSS 标签。若只有 `cua.createBrowserTab('iab', url, options)` 就从此入口开始；示例是能力提示，不保证所有宿主都有该 API。
2. 获取页面 AX 或 DOM，核对网址、列表、搜索框及登录状态。若初次只有“加载中”，允许正常加载后再观察。
3. 若文档提供 `agent.browsers`，按实际返回的 browser ID 和 tab ID 取得同一标签的 Playwright 句柄；不要硬编码 ID 或通过 shell 启动其他控制通道。
4. 用当前 DOM 中已观察的定位器进行低风险测试：读取职位列表，给搜索框 fill 用户指定关键词，再执行搜索，核验结果标题/查询参数。每次操作后检查状态，不能把未抛错等同于成功。
5. 若未登录，标记需要用户登录；登录前的基础读取通过不代表已验证完整投递链路。不得用点击“立即沟通”作随意连通性测试。

只在工具文档支持时使用以下模式：

```js
// browserId、tabId、role/name 都来自本轮观察，而非固定常量。
const browser = await agent.browsers.get(browserId);
const tab = await browser.tabs.get(tabId);
const snapshot = await tab.playwright.domSnapshot();
// 根据 snapshot 找到真实输入框后 fill，再读取新状态。
```

`playwright.evaluate` 若仅允许只读，则只用于读取 DOM；不得注入点击脚本、访问隐藏状态、直接调用网站接口或替代受限的 UI 动作。已有 userscript 模式与此模式独立，不能同时驱动发送。

## 闪烁、重载与定位失败

- 出现持续闪烁/重载，停止一切动作。关闭助手创建的测试标签可止闪；用户原有标签先征求是否关闭，或用工具提供的停止加载操作。不要连续重建页面试探。
- `No node found at given location` 可能发生在页面重建后，不据此断定是账号、API 登录、反爬或用户权限问题。先按当前浏览器故障文档检查，获取一次新状态；若继续失败或重载则结束这条试验路径。
- 记录区分：可打开、可读取、可填写、可点击、搜索结果可核验、已登录、发送已核验。未通过哪一项就报告哪一项，不能笼统说“完全可用”。
- 不在故障回执含糊时反复点击发送。切换可用浏览器需要重新核对账号与台账，保留所有在途记录。

## 本项目实测边界

一次 BOSS 未登录页面试验中：IAB 可打开页面，Playwright 可读取岗位列表，fill 后 AX 能读到搜索词；搜索链接点击报定位错误，后续页面反复加载并出现闪烁。已关闭测试标签，未发送任何消息。

因此本路径是可探测的候选路径，不是已验证稳定的 BOSS 全链路方案。该试验没有使用自定义 API 账号，不能推断自定义 API 用户也成功或失败。后续必须在实际环境完成上述分项探测，再决定采用 IAB、已连接 Chrome 或桌面路径。
