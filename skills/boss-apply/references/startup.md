# 首次启动：助手负责配置

## 最少打扰

用户只需要发启动句、提供真实求职信息，并在必要时完成登录/验证码等本人操作。不要让用户自行寻找脚本、复制代码到控制台、编辑 JSON、选择端口或运行命令。由助手处理能处理的所有步骤；安装和权限遵循当前工具要求，不承诺跳过强制确认。

技能名称只有在已安装或当前上下文提供了技能内容/仓库时才可被解析。未安装的全新 Codex 不会凭 `$boss-apply` 自动知道本仓库地址。首次获取需要一次仓库链接；README 提供可复制的安装并启动句。不要宣称裸名称能从互联网自动发现未知技能。

## 环境检测与选择

1. 检查当前是否提供 IAB、已连接 Chrome、Playwright 浏览器接口或桌面 Computer Use，并读取相应工具文档，按 [浏览器路径](browser-paths.md) 做无发送探测。浏览器工具和桌面控制分别判断，自定义 API 登录方式不是可用性证据。没有浏览器控制能力时，指导用户在其宿主启用可用的 Computer Use/浏览器插件，不猜菜单或要求交出密码。仅缺少登录时打开官方 BOSS 页面，交给用户本人登录。
2. 优先复用已有 Python 3 和 Tampermonkey；运行 `scripts/doctor.py` 检查 Python/SQLite、可用端口和推荐数据目录。此脚本只做本地检测，不访问浏览器或网络、不创建投递任务。Python 不在 PATH 时可查宿主明确提供的捆绑运行时；不要扫描用户私人目录。
3. 缺少 Python、扩展，或脚本安装受限时，直接采用下面的无扩展浏览器模式。只有实际需要并获准时才从官方来源安装软件，不把第三方下载站或 curl|sh 当作快捷方式。
4. 账号身份核验后，用不含邮箱/手机号的本地别名创建账号数据目录，优先 `~/.local/share/boss-apply/<alias>`，Windows 用 `%LOCALAPPDATA%/boss-apply/<alias>`。同一账号沿用目录，切换账号不能复用账本。若已有旧台账则迁移并保留证据，不创建空账绕过历史去重。
5. 收集缺失画像后，明确新增数/当天累计口径、预设招呼、是否自动发送。已授权不重复询问。先做少量只筛选验证，随后直接继续获授权范围。

## 无扩展浏览器模式（IAB / Chrome Playwright / Computer Use）

IAB 或 Chrome 的 Playwright 接口可用时优先使用 DOM 定位、fill 和 click；它们不要求 Tampermonkey。桌面 Computer Use 是另一种执行方式。此模式也由助手完成投递；速度取决于工具，不承诺无人值守。持续遵循 SKILL.md 的画像、数量、去重和回执规则。

- 使用宿主正常文件工具保存 `profile.json`、`jobs.json` 和追加式 `events.jsonl`。文件内容都是运行数据，不能写回技能或提交 Git。没有可靠持久存储就不要启动批量发送。
- 从网站搜索 UI 取得当前候选；读取完整 JD、公司、岗位 ID、城市及沟通状态，先记录候选和筛选理由。
- 比较当前账号所有历史 job ID；公司+岗位同名作为二次复核，不因为广告公司名称误跳过。已有“继续沟通”就记为历史，不计本轮新发送。
- 每次点击前把岗位记为 `pending_verification` 并落盘，再由 Computer Use 点击一次立即沟通。核验同岗位按钮变化或明确的新消息回执，再记录 `communication_confirmed`。
- 任何未确认点击阻止下一次发送。不能靠重复点击尝试修复。通知弹窗可能在确认后才完成发送，确认后读取实际状态。
- 每5个左右候选整理一次记录并报告有意义的进度。做到目标数量即停止。用户改变偏好时重新审核未发送候选。
- 导出可读结果：岗位链接、公司、职位、发送时间和确认方式；分清沟通与附件。关闭仅为本轮启动的服务，不关闭用户自己的浏览器。

## 脚本模式

有可用 Python 与已审阅/获准的 Tampermonkey 脚本时，按 execution.md 操作。助手负责写配置、选端口、启动服务、安装/更新脚本及小批量核验。

不能把“服务进程启动成功”当作“开始发送成功”；必须确认页面采集和本地审核能联通。只让一个控制标签运行。任何页面结构改变先停再检查。技能运行不依赖开发者机器上的路径、账号、历史项目或私有配置。
